# V02 loggia source-lighting candidate — incomplete district release

`SIGHTLINE_SAINT_MERIDIAN_V02_DIFFUSE_LIGHTING.html` derives from the uploaded Loggia Terraces checkpoint. The older entry, current-candidate pointer and GitHub snapshots are preserved. This is a bounded architectural lighting improvement, not full V02 acceptance.

The three public rooms at 40, 68 and 100 m now use a real Blender diffuse-light atlas and a separate reflected-radiance probe per room. Twelve existing ceiling strips receive a private source material with emission strength 34 instead of 0.85. Global exposure, bloom, nine dynamic lights, fog, original city materials and all gameplay code remain unchanged. Room geometry, base UVs, normals, tangents, collision and ownership are preserved. Source lookup/provenance and exact hashes are in the authoring, master validation, packaging and build JSON reports.

The 1024² atlas uses 1024 Cycles samples and stores scene-linear RGBA16F texels. Diffuse contributions replace native direct/ambient/IBL diffuse on fifteen private opaque materials; original PBR specular and emission remain. The old approximate soffit emission hook is absent on these clones. Three 512×256 panoramas use 64 samples and source denoising, followed by the existing Three.js PMREM pipeline. All 21 private room materials use their own room's reflected radiance. Original rigs, powers, missions, animation, physics and camera code are unchanged.

The export partitions existing triangles into three tightly bounded room nodes. It does not add triangles. All 13,032 source corners retain positions, normals, tangents and UV0, plus independently verified UV2. Partitioning uses the actual recorded room extents, including underfloor beams. A whole-district view can require up to 14 extra material draws; room-local culling can eliminate the other floors. This bound is not a whole-world performance claim. Each room currently uses one static probe without box-projected parallax. Moving actors, newly cast effects and later destruction are absent from these static reflections.

## Reproduction

Run from the worktree, with its existing HTTP server on 8766:

1. Blender CLI `--background --factory-startup --python-exit-code 1 --python scripts/vertical-v02/blender_diffuse_pilot.py` authors UV2, source fixture materials, the diffuse atlas and three probes, saving a separate master.
2. Run the same Blender CLI with `scripts/vertical-v02/validate_diffuse_pilot_master.py` to independently reopen it, verify source preservation and packed image identity, and emit source UV witnesses.
3. `node scripts/vertical-v02/package_diffuse_pilot.mjs` verifies prior rendered corners, all source UV witnesses, room partition identity, material/HDR parameters, exact optimization parity and Khronos validation.
4. `python3 scripts/vertical-v02/build_diffuse_lighting.py` reproduces the complete candidate entry. Its inverse verifies that only the manifest selector and appended source-lighting adapter differ from the immutable parent.
5. `node scripts/vertical-v02/test_diffuse_lighting.cjs` boots the real parent and candidate, checks original-city/contact preservation, source-texture GPU sampling, per-room material ownership, matched views and three ordinary-input room visits. Starts and camera-only bookmarks are labelled fixtures, not claims of complete routes.
6. `python3 scripts/vertical-v02/run_diffuse_lighting_checks.py` runs the 18 retained HUD/input checks and installed web-game client after explicit lighting readiness. This includes simulated controller, portrait/landscape touch, hero switching and encounter controls; physical devices remain untested.
7. Blender CLI with `scripts/vertical-v02/render_diffuse_lighting.py` renders the saved source using the current actual browser camera matrices. Source and browser shading remain distinct; these images do not prove pixel fidelity.
8. With other automated rendering jobs stopped, `node scripts/vertical-v02/benchmark_diffuse_lighting.cjs` records sequential parent/candidate 60-simulation-second native-RAF lower-loop workloads at fixed 1280×800, including GPU timers where supported. It does not replace the final combined combat/replay/destruction stress scenario.

## Retained failures and limits

Independent comparison caught changed normal-map tangents when the new UV2 was active during export. The author now selects UV0 before tangent export and UV2 explicitly for baking; the failed payload and script remain under `initial-uv2-tangent-failure`. The first diffuse bake was too dark; it used the old low-output accent strips. The 64-sample brighter bake was visibly noisy. Both are retained as rejected experiments. A calibration harness initially assumed direct mesh children, a draw test incorrectly required identical dynamic-world visibility, a later test confused opaque material sort order with added draws, and source optics initially sampled points far outside the room frustum. Their failures and corrected scopes are retained. The first room partition omitted underfloor beams; corner conservation failed and now uses recorded physical room bounds.

Current screenshots show improved warm floor/ceiling response. Residual bake noise, reflection parallax, the original building wall's different native/source response, and broader district architecture/material coherence remain open. The default camera can still crop Backspool's lower body in these confined rooms, and retained combat/Echo views have framing failures. Full approved-reference visual quality is **FAIL / incomplete**. Final mission/destruction/failure coverage and the combined active GPU-aware release workload remain open. This lighting candidate does not close those gates or certify the complete movement graph.

## Measured bounded workload

The sequential parent/candidate runs each cover 60 simulation seconds and 640.654 m at a fixed 1280×800 internal resolution; sampled player and camera positions match exactly. Frame intervals p50/p95 were 8.9/17.5 → 8.6/18.0 ms; simulation CPU 8.7/16.3 → 8.7/16.8 ms; GPU 6.7168/8.9662 → 6.7228/9.1382 ms (1202/1186 valid queries, no disjoint samples). World draws p50/p95 were 410/506 → 412/507; rendered triangles 1,692,206/1,830,165 → 1,674,266/1,827,225. Different RAF sampling and moving-actor visibility affect those distributions; triangle changes are not geometry optimization claims. Loading was 8.660 → 8.779 s. Both runs had no runtime errors.

Coarse heap snapshots reported 322 MB used / 410 MB allocated at start/end in both runs. These are neither peak-memory nor leak measurements. The inherited dropped-time counter reported 0.2619 / 0.1627 s but omits time discarded by the scheduler's outer elapsed clamp. CPU submission time is recorded separately from asynchronous GPU timing. Videos and chronological review sheets are retained; video wall timestamps are not certified simulation-frame matches. The combined combat/replay/destruction workload and physical devices remain outside this measurement.
